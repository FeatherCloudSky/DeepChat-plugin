# DeepChat-plugin

接入任意 **OpenAI 兼容 / Anthropic 兼容** API 的拟人聊天插件（Yunzai 系框架）。

配置界面走 [锅巴插件](https://gitee.com/guoba-yunzai/guoba-plugin)，全部选项可视化，不需要手改 JSON。

## 已在什么环境上验证

**TRSS-Yunzai** + **DeepSeek V4.1 Flash**，实机跑通——包含帮助图、群聊与私聊对话、
AI 名称与关键词触发、图片识别、引用图片、每会话开关、权限体系、锅巴面板。

插件是按 Yunzai 插件体系的**通用接口**写的，没有用到某个分支特有的东西：

| 用到的宿主能力 | 备注 |
|---|---|
| `plugin` 基类、`rule` / `priority` / `accept` 钩子 | Yunzai 插件体系通用 |
| `e.runtime.render(..., { retType: 'base64' })` | 出图；宿主不支持时自动退回纯文本帮助 |
| `redis` / `logger` 全局量 | 上下文缓存与日志 |
| `e.group.getChatHistory` / `e.friend.getChatHistory` | 引用图片、附加上下文（icqq 接口） |
| 插件目录下的 `guoba.support.js` 的 `supportGuoba()` | 锅巴面板；锅巴自身对 Miao-Yunzai / TRSS 都有适配 |

其它要求：**Node.js > 16.14**（`fetch` 兜底见 `model/http.js`）、**Redis 可用**、
**安装锅巴插件**，以及**服务器装了中文字体**（否则帮助图的汉字全是方框，见下文说明）。

## 安装

```shell
cd plugins
git clone https://github.com/FeatherCloudSky/DeepChat-plugin
cd ..
# 重启 Yunzai
```

目录名保持 `DeepChat-plugin` 即可（插件用自己的 `import.meta.url` 定位资源，放哪都能跑）。

**运行环境**：Yunzai 系框架声明的最低环境是 `Node.js > 16.14`（Miao-Yunzai 3.1.3 的 README 写的就是这个），而全局 `fetch` 要到 Node 18 才默认可用。
插件对此做了兜底——探测到没有 `fetch` 时自动退回 `node:http` / `node:https`，所以 16.14 以上都能跑。
当前走的是哪条链路，`#chat状态` 里会直接写出来。

## 聊天记录

| 命令 | 作用 |
|---|---|
| `#记录` | 开始记录**当前会话**（群或私聊） |
| `#记录状态` | 看已经记了多少条、从什么时候开始 |
| `#结束记录` | 结束并把记录打包发出来 |
| `#取消记录` | 丢弃这次记录，不发出 |

只有**主人 / 管理员**能操作。输出方式在面板「聊天记录」标签页里配：`auto`（默认，三级降级）/ 合并转发 / md 文件 / 纯文本。

**为什么要三级降级**：合并转发用的是 `e.group.makeForwardMsg()`，而 icqq 0.6.10 的类型定义里根本没有这个方法（Yunzai 自己也是先判断存在再用）；md 文件用 `Group.sendFile()` / `Friend.sendFile()`，两者签名还不一样（`(file, pid?, name?)` vs `(file, filename?)`）。所以没有任何一级保证可用，`auto` 会一路降到纯文本，保证你总能拿到东西。

**前提：只能记到「插件收得到的消息」。** Yunzai 的 loader 在派发事件前会先跑 `onlyReplyAt()`：

```js
if (!e.message || e.isPrivate) return true            // 私聊永远放行
if (groupCfg.onlyReplyAt == 0 || !groupCfg.botAlias) return true
if (e.atBot) return true                               // 被 @ 才放行
if (e.hasAlias) return true                            // 带前缀才放行
return false
```

所以在**群聊**里，只有该群设成「不限制」（`onlyReplyAt = 0`）时才能记全；设成「仅 @ 时响应」的话普通消息根本到不了插件，记录会几乎是空的。真的一条都没记到时，`#结束记录` 会把这条原因直接告诉你。

存储是**一条消息一行**追加写进 `data/record/*.jsonl`：群聊刷屏时也不会有明显 IO；**机器人中途重启记录还在**，重启后自动接着记；开了记录却没发 `#结束记录` 的，超过「未结束的记录保留时长」会被自动清理。

## 权限（主人 / 管理员）

在「权限设置」标签页里按 QQ 号配置：

| 角色 | 数量 | 能做什么 |
|---|---|---|
| 主人 | 1 个 | 全部权限，包括 `#结束全部对话`、`#chat全开` |
| 管理员 | 最多 5 个 | 开关 / 重置会话，查看状态 |
| 普通成员 | — | 对话、查看状态、`#结束对话`；开关会话默认不允许 |

判定规则有几个细节：

- **留空主人 QQ** 时，沿用 Yunzai 自身的 `e.isMaster`（即宿主配置的机器人主人）。
- **填了主人 QQ 之后，Yunzai 的主人依然保留主人权限** —— 插件不应该把机器人主人削弱掉。
- **管理员最多生效 5 个**，配置里多填的会被忽略，并在日志里写明忽略了哪些。
- 数字和字符串形式的 QQ 号都能匹配（`10001` 与 `"10001"` 视为同一人）。
- 「允许普通成员开关会话」默认关闭；打开后群成员可以自行 `#chat关` 让机器人闭嘴。

`#chat状态` 会直接告诉你当前身份：`你的身份：主人 / 管理员 / 普通成员`。

## AI 名称触发怎么算

**默认是关键词包含**：消息里**任意位置**出现这个名字就算命中，**不需要 @**。

| 配置 aiName | 消息 | 是否触发 |
|---|---|---|
| 达达利亚 | 不知道达达利亚圣遗物带什么好 | 触发 |
| 达达利亚 | 今天天气不错 | 不触发 |
| C++ | 我在学C++ | 触发（按字面匹配） |

打开「把 AI 名称当作正则」后改按正则匹配，适合下面两种情况：

- 名字里带 `.` `*` `+` `?` 这类符号，而你**希望**它们当通配符用；
- 想一次匹配多个名字，例如 `达达利亚|公子`。

正则写错时（括号没闭合之类）会自动退回关键词匹配并在日志里提示，不会让回复链路崩掉。

## 触发关键词

「基本配置 → 触发关键词」可以再配至多 20 个词，消息里出现任意一个就触发主动回复。
它和 AI 名称是同一类东西（都算「明确叫到 AI」），区别只是名称只有一个且可选正则，
关键词是一组且永远按字面匹配：

| 配置的触发关键词 | 消息 | 是否触发 |
|---|---|---|
| 小助手、机器人 | 小助手在吗 | 触发 |
| 小助手、机器人 | 今天天气不错 | 不触发 |
| `\d+` | abc123 | 不触发（按字面找 `\d+` 这四个字符） |

超出 20 个的会被忽略，并在日志里写明忽略了哪些；重复的词自动去重。

## 名称与关键词走的是主动模式

这两者都算「明确在叫它」，所以：

- 使用**主动模式**的温度 / token 上限，而不是伪人模式的那一套；
- **不受伪人黑白名单限制** —— 伪人黑名单是给「随机接话」准备的，不该让点名也失灵；
- 仍然受会话级开关（`#chat关` / 强制停用的群）控制，关掉就是彻底不回。

如果希望某个群彻底安静，用「强制停用的群」，而不是伪人黑名单。

## 会话启用判定顺序

从高到低：

1. 私聊总开关「允许私聊使用」——关掉则私聊一律不响应
2. 会话级单独设置（`#chat开` / `#chat关`，写入 `data/state.json`）
3. 「强制停用的群 / 私聊用户」列表
4. 「强制启用的群 / 私聊用户」列表
5. 全局「默认启用 AI」

伪人模式的触发另有群 / 用户黑白名单，只影响**被动接话**，不影响 `#chat` 和艾特。

## 图片输入

「模型能力」标签页里可以逐模型声明是否支持图片：

```
模型名           支持图片输入
gpt-4o           开
deepseek-flash   开        ← DeepSeek V4.1 Flash 原生多模态
deepseek-chat    关
*                关        ← 没列出的模型走这条
```

- 当前模型**支持**图片时，消息里的图片会转成多模态内容（OpenAI 用 `image_url` 块，Anthropic 用 `image` 块）。
- **不支持**时自动退化成文字标记（默认 `[图片]`），模型至少知道有图。
- **「下载图片后以 base64 发送」强烈建议开启。** 不开的话，是把 QQ 的图片链接直接交给服务商
  让它自己去下载——而 QQ 的图片是带鉴权、有时效的临时地址，服务商多半拉不到，**症状就是「模型看不到图」**，
  模型只会看到 `[图片]` 三个字。开启后由插件先下载、再以 base64 内联发送，最可靠。
- 图片来源优先用本地临时文件转 base64；本地文件不存在时才用 URL。
- **图片细节级别**（`imageDetail`）：对应 OpenAI 兼容协议里的 `image_url.detail`。
  `low` 会先把图缩到 512×512 再推理——**更快、更省 token**；
  `original` / `high` 保留原图；`auto` 由服务商决定（目前等价 original）。
  **留空则不发送这个字段**，因为不是所有兼容服务商都认它，留空最保险。
- **支持引用图片**：在 QQ 里「引用」一张图片再 @ 机器人，插件会去**被引用的那条消息**里取图。
  因为 QQ 引用图片时，图片在**被引用**的消息里，当前消息只有一个 `reply` 段——
  直接看当前消息是找不到图的。icqq 没有「按 id 取单条消息」的接口
  （`Group`/`Friend` 只有 `getChatHistory` 和 `recallMsg`），所以是从最近 30 条记录里翻；
  引用**很久以前**的消息可能取不到，这种情况会在日志里说明，文字部分照常回复。
- 写入缓存时图片一律替换成 `[图片]` 文字——base64 留在 Redis 里既占内存又没有意义，
  图片只需要在**当前这一轮**发给模型。

## 协议怎么选

| 服务商给的接口 | 开关「使用 Anthropic 协议」 |
|---|---|
| `https://xxx/v1/chat/completions` | 关闭 |
| `https://xxx/v1/messages` | 打开 |

API 地址只填基础部分（到 `/v1` 为止），插件会自己拼 `/chat/completions` 或 `/messages`。
**留空**时会按所选协议回落到官方地址，并在日志里提示。

Anthropic 协议有几个硬性要求，插件已自动处理：`system` 提到顶层、`messages` 不能出现 system 角色、
消息必须 user 开头且角色交替（连续同角色会自动合并）、`max_tokens` 必填。

## 帮助图与背景自定义

帮助内容不是写死在代码里的，而在 `resources/help/help.md`：

```markdown
# DeepChat 帮助

## 对话
- `#chat 内容` — 主动和 AI 对话
```

解析规则：`#` 是一级标题，`##` 是一个分组，`- 命令 — 说明` 是一条帮助项
（分隔符支持 `—`、`——`、`-`、`:`）。改完 md 重启即可，不必碰代码。

配置面板的「帮助图」标签页负责外观：

| 配置项 | 说明 |
|---|---|
| 帮助背景 | 留空用插件自带的背景；可填本地路径、`http(s)` 链接或 `file://`。相对路径按 Yunzai 根目录解析 |
| 背景暗化程度 | 背景上压一层黑色遮罩，0 ~ 95，越大文字越清楚 |
| 背景模糊 | 背景模糊半径（px），0 表示不模糊 |
| 帮助图强调色 | 标题、分组名、左侧竖条的颜色 |
| 帮助图标题 / 副标题 | 留空则用 md 的一级标题 / 插件名 |
| 帮助图宽度 | 渲染宽度，600 ~ 2400 |

**默认背景**用的是用户提供的图（原图 5000×5000 的 JPEG，仅扩展名是 .png），
进插件前缩到了 1600×1600、424 KB —— 帮助卡片宽度才 1200px，
留着 2500 万像素每渲染一次都要多解码几秒。

### 出图需要服务器装中文字体（重要）

帮助图是在**服务器上**用 puppeteer 渲染的，用的是**服务器的字体**。
Windows / macOS 自带的中文字体在 Linux 上并不存在——如果服务器没装中文字体，
**图片里的汉字会全部变成方框（tofu），而英文、数字、符号完全正常**，这就是最典型的症状。

装一款即可：

```bash
# Alibaba Cloud Linux / CentOS / RHEL
sudo yum install -y wqy-zenhei-fonts wqy-microhei-fonts

# Debian / Ubuntu
sudo apt update && sudo apt install -y fonts-noto-cjk

# 装完刷新一下字体缓存
sudo fc-cache -f -v
```

模板的字体栈已经覆盖 Noto Sans CJK / 思源黑体 / 文泉驿系列，装其中任意一款都能被认到。
装完**重新发一次 `#DeepHelp`** 就会正常（不用重启）。

如果宿主不支持渲染（`e.runtime` 缺失或没装 puppeteer），`#DeepHelp` 会自动退回
纯文本形式，不会变成一个报错。

## 隐私提醒

- 开启「伪人模式」并**不限制群**时，群里最近的聊天记录会随上下文发给 API 提供方，包含群昵称、群名片、头衔、群号。
  建议先用「伪人群白名单」限定生效群，或把「附加聊天记录条数」调小 / 设 0。
- `data/cfg.json` 里存的是**明文 API Key**。锅巴面板本身有鉴权，但请勿把该文件分享出去。
- 建议用专门申请、带额度上限的 Key，不要复用主力账号的 Key。

## 自检

插件自带两个脚本，不依赖 Yunzai 环境，克隆下来就能跑：

```shell
cd plugins/DeepChat-plugin

node test/offline-check.mjs        # 行为回归：协议转换、配置、策略、权限、拆条、全链路
node test/consistency-check.mjs    # 一致性：配置键 / 面板字段 / 模板变量互相是否对得上
```

- `offline-check.mjs` 会 mock 掉 Yunzai 的 `plugin` / `logger` / `redis`，然后用一个**本地假 API 服务**
  真发请求，覆盖两种协议的请求体与请求头、图片的 URL / base64 两种形态、
  以及从「一条群消息」到「分条回复 + 写缓存」的完整链路。
- `consistency-check.mjs` 专门抓漂移：代码里 `Cfg.get*('x')` 读的键、
  锅巴面板暴露的字段，是否都在 `cfg_default.json` 里有默认值；模板用的变量是否都由
  `buildRenderData()` 提供。这类问题普通单测发现不了，但上线就炸。

两个脚本都以退出码表示结果，可以直接接进 CI。
